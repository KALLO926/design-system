# 机械质检

本技能将判断方法与确定性制作分开：模型负责理解、提炼和页面设计；工具负责加载、检查、渲染和出图。本文件迁移自 yu-apple 的 deck.mjs 工具纪律，适用于单页 HTML 与演示型页面。

## 检查什么（自动）

- **缺图 / 资源加载失败**：图片、图标、字体未按预期加载 → 非零退出并报告来源。
- **文字裁剪 vs 可见溢出分开判**：元素自身或祖先真实裁剪（overflow hidden 切掉字形）算失败；字形盒内可见溢出只作排版复核警告，不误判为裁切。
- **画布偏移**：整体边距导致内容被推出可视区 → 报告坐标。
- **浏览器错误**：页面脚本报错、资源 404 一并收集进检查报告。
- **版本一致性**：源文件或本地素材变化后全部重渲，防止旧图混入新总览；局部更新只重渲受影响区块，但总览必须由完整最新缓存生成。

## 怎么跑

- 演示稿形态（`.viewport > .slide[data-page]` 合同）：直接用原包工具 `~/workspace/custom-skills/yu-apple/scripts/deck.mjs` 的 `check / render / pdf`（参数见原包 references/tooling.md）。
- 普通网页：用 Playwright 打开本地文件，桌面（如 1440 宽）与移动端（390 宽）各截全页图＋逐区块图，脚本检测横向溢出、元素裁剪与图片加载状态，输出与截图并排的总览供目检。

## 对齐审计（自动测量，不靠眼估）

用脚本量实际渲染盒，逐项核对，偏差 >1px 即记问题：

- **版心左边缘**：各区块的眉题、标题、正文左 x 应落在同一条版心线上（居中区块与容器内缩进单独标注为有意为之）。
- **并列项基线**：同组并列项（数字组、能力卡、步骤卡）的图标顶、标题顶、正文顶三组 y 值应分别相等；数字与单位共基线。
- **表格列边缘**：每一行的各列左 x 应逐行相等；表头与正文列共用同一组左边缘。
- **重复条目节奏**：同类条目（如要点列表）的标题间距应等距。
- **页眉垂直居中**：Logo、导航、按钮的垂直中心应在同一水平线上。
- **字体环境声明**：测量只对当前渲染环境的字体成立；交付环境字体不同（如 Windows 微软雅黑 vs 测量端 Noto Sans CJK）时，字形级垂直居中与断行可能漂移，交付说明中须注明以用户打开环境为准。
- **墨迹中心（居中标题必查）**：盒模型居中 ≠ 墨迹居中——全角标点（，。）墨迹只占字格左下，行尾带标点时整行墨迹会被推偏约 0.3 字宽，盒测量查不出来。跑 `scripts/ink-center-check.py <html>`（扫截图墨迹逐行验中心，容差 max(2px, 字号×0.05)，桌面＋移动端各一遍），FAIL 不交付。
- **源头默认（防墨迹偏移）**：居中大标题默认行尾不放全角标点，断句靠换行；必须保留标点时，用 ink-center-check 复测并按实测偏移补偿，不许凭感觉。

## 目检（不可省）

自动检查无法识别所有视觉重叠。交付前逐区块看全尺寸截图：断行、图标、来源、对齐、裁切与素材真实性；深色区、渐变文字、阴影、透明层是重点。字体或运行环境变化后，至少复核命题区、复杂信息区和包含特殊效果的区块。

检查结论只报实际验过的部分：只跑了自动检查，就只说自动检查通过，不说视觉已验收。
