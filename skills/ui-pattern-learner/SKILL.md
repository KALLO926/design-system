# 学习维度与边界（2026-11-21 kk 交付《UI 审美与设计能力学习说明》，原文存档于 design-research-library/ui-learning-curriculum-2026-11-21.md）

核心原则：学底层秩序与工程工艺，不学易过时的视觉表皮（特定配色模板、流行圆角、装饰特效）。

- **学习维度（由浅入深）**：L1 秩序与微弱层级（排版比例、4/8 步进、同心圆角、低透明度边框、Surface Delta）；L2 边缘状态与微交互（空/加载/报错/溢出态、状态差值与缓动）；L3 信息密度与渐进式披露（常驻 vs 折叠/hover 显现、高密度降噪）；L4 语境、立场与设计决策。
- **人机边界**：L1/L2 由 Agent 主学（脚本采样＋沙盒验证）；L3 由 Agent 学、靠减法审查纠偏，信息架构取舍归 kk；**L4 归 kk**——Agent 只记录观察到的品牌语境与立场，不替产品下立场结论、不自选跨界方向（建筑/印刷/工业设计/电影等跨媒介素材为人类主导，kk 点名时才执行）。
- **素材六类轮换**：品牌官网与落地页；高密度生产力工具；金融与数据面板；无头与原子组件库；编辑部与内容网站；真实上线网站的真实组件（2026-11-21 kk 补）。各类标杆名单**只是示例、不是封闭清单**（2026-11-21 kk 明示）：选材池维护在 design-research-library/learning-sources.md，Agent 须自行搜集扩充——遇到同类优秀对象打开本体核实后入池；选材优先从池里选，池里没有合适的现找现核实再学。
- **每日选材配额（2026-11-22 kk 定，复盘后入正本）**：每日 3 个对象，分属不同类别；非组件类（区块、页面模式、排版系统、交互/状态系统）至少 2 个，组件类最多 1 个。不许靠轮换运气决定类别构成。
- **选材可复现性预筛（2026-11-23 kk 拍板 1A）**：选材时先判对象的视觉主角是否可复现——主角是照片纹理、专有字体（如点阵字）、手绘/照片抠图形象、视频的对象，临摹环节天然复现不了原物。预筛结论决定学法：主角不可复现时，优先换同类里可复现的对象；确有学习价值要学的，临摹时资产层用占位并标注，按 Step 4 分层验收走（结构层判过不过，资产层差距只记录）。依据：2026-11-23 三对象全灭（Nothing 专有字体、Wise 照片纹理、Pudding 照片抠图），卡点全在资产层而非结构层。
- **避坑三条**：不学概念飞机稿；不学「静态成功态」——功能型产品优先学内部界面（工作台、设置页、弹窗、表单）与边缘态，只看数据填满的首页不算学到；学关系不背色值（记「背景与卡片 4% 明度差」这类关系，不死记十六进制）。

# 选材红线 (Source Filtering)

- **优先学习对象**：经过真实高密度业务考验的生产级产品与无头组件库（如 Linear、Stripe、Vercel、Raycast、Radix UI、shadcn/ui）；真实上线运营的优秀网站（品牌官网、产品官网）同样在列，学其真实组件与区块（2026-11-21 kk 补：网站也要包括）。
- **严禁学习对象**：禁止直接抓取 Dribbble、Behance 上的概念飞机稿，以及充斥重阴影、高饱和渐变、无实际交互逻辑的视觉展示页。
- **核心原则**：**绝不直接将原始 HTML/CSS 源码塞入知识库**；必须剥离业务逻辑，只提取“数学比例、状态差值、克制意图与验证后的纯净代码”。

# 标准化学习流水线 (Learning Pipeline)

当用户提供一个目标 URL 或指定组件区域时，Agent 必须严格按以下 5 步执行：

### Step 0: 本地化存档 (Localize First)（2026-11-22 复盘新增，获奖站全程实证）
外站对象开工先落本地档，后续采样、状态采集、临摹对照全对本地档做，不反复打原站：整页/整站用 monolith 存单文件档（`~/workspace/tools/monolith/monolith <网址> -o <档.html>`，贾维斯可独立完成）；需要逐资产分析时再用 curl 镜像法存一份文件夹镜像。理由：extract 自带浏览器连不上外站、原站会改版或下线、流媒体与签名资源有过期窗口——先存档，证据不丢、断网可复现。本地自有页面跳过本步。

### Step 1: 计算样式与比例采样 (Computed Style Extraction)
**先行底稿（2026-11-22 kk 定，designlang 试跑实证）**：目标为可公开访问的整页/整站时，先跑 `npx -y designlang extract <URL>` 出底稿（DESIGN.md＋DTCG tokens＋motion tokens，约 2 秒；浏览器缺失时先跑一次 `npx -y designlang install-browser`）。底稿只作采样初稿：色值、字阶、间距阶、动效参数仍须用下方 getComputedStyle 采样抽查核对，底稿与实测不符以实测为准；目标是页面内单个对象、或页面需登录态时，跳过底稿直接采样。designlang 的 fidelity 总分与 verify-ui 经实测不可靠，不许用作验证依据（2026-11-22 试跑：文字色全变 fidelity 仍给 100 分、整页变红 verify-ui 漏检）。
**外站先本地化（2026-11-22 kk 定，获奖站实测）**：extract 自带浏览器在本机连不上外站（代理限制），量外站先把页面本地化：用 curl 逐个下载首页 HTML＋全部 CSS/JS/图片/字体资产、改写为本地相对路径（wget 下不全，禁用；JS 运行时动态加载的字体需手动补 @font-face，视频分片流可不下、不影响量测），起本地 http.server 后对 localhost 地址跑 extract。需要「整个网页存成单个文件」交付或存档时，用 monolith（贾维斯可独立完成，2026-11-22 kk 定）：`~/workspace/tools/monolith/monolith <网址> -o <输出.html>`，其 HTTP 客户端认环境代理、可直连外站，一条命令把 CSS/图片/JS 全部内嵌成单个 HTML（实测获奖站 13MB、断网可打开；运行时动态拉的字体与流媒体视频仍包不进，交付时如实注明）。重页面（资产多、动效多）禁用 `--interactions`（实测 280 秒超时零产物），只带 `--wait 3000 --motion-runtime` 约 10 秒可跑通。extract 可信项：颜色与面积占比、间距阶、圆角、动效时长；不可信项（必须 getComputedStyle 抽查复核）：前景色归纳、字体归属统计、字阶主值、scrollLinked 判断（实测把常驻环境动画误判为滚动联动）。**强制复核清单（2026-11-22 复盘定）**：不可信四项不是抽查、是必查——逐项用 getComputedStyle 复核并在解剖卡里标注实测值后，才准进入 Step 3；未复核的底稿数据不许出现在完成报告里。
使用无头浏览器打开目标页面并定位目标组件，运行脚本调用 `window.getComputedStyle()` 提取真实渲染属性，严禁直接照搬未清洗的原始类名或嵌套 DOM：
- **排版比例**：提取主标题、副标题、正文、辅助文字的 `font-size`、`line-height`、`font-weight`、`letter-spacing` 及相互比例。
- **微弱层级**：重点抓取低透明度边框（如 `rgba(255,255,255,0.08)`）、相邻层级的背景明度差（Surface Delta）以及阴影参数（若无阴影则显式标记为 `none`）。
- **间距与圆角**：记录 `padding`、`gap` 和 `border-radius`，检查内外容器是否遵循“同心圆角法则”（外圆角 = 内圆角 + 间距）。
- **登录墙降级规则**（2026-11-21 kk 定，总文档 v1.1）：若目标内部界面存在登录墙，优先切换至该产品的公开 Demo / Sandbox / Storybook；若无公开态则直接跳过、换素材池下一个对象，严禁在登录页空转。极高价值但强登录的产品，留待 kk 提供已登录态或截图时再拆。

### Step 2: 交互状态差值采集 (Interactive State Delta)
对目标组件执行自动化交互动作（`hover`、`focus-visible`、`active`、`disabled`，以及暗黑/明亮模式切换），记录**变化前后的样式差值（Delta）**：
**降级路：DOM 状态考古（2026-11-22 复盘新增，获奖站实证）**：自动交互采不到时（`--interactions` 在重页面超时、重 JS 站触发不动），不许跳过状态差值——改读本地档的 DOM 结构推状态机：数据属性（如各行绑定的媒体/目标）、隐藏节点与备用状态块、类名语义、JS 里的状态切换逻辑，再用截图做状态对照验证。获奖站的「悬停切视频」联动与头部白卡展开态即靠此路查清；纯靠自动交互这两项都采不到。
- 明确记录变化维度（例如：仅背景透明度 +4%，无位移、无缩放）。
- 提取动效参数：`transition-property`、`transition-duration`（通常在 100ms–200ms 之间）以及精确的 `cubic-bezier` 缓动曲线。

### Step 3: 双模态审美解剖 (Bimodal Anatomy)
将**组件渲染截图**与 **Step 1–2 提取的数据**同时输入视觉分析步骤，输出一份精简的《组件解剖卡》，必须回答以下 3 个问题：
1. **克制点（What was omitted）**：它刻意去掉了哪些平庸设计常加的元素？（如：去掉搜索框外边框、隐藏次要操作直到 hover 显现）。
2. **层级手段（Hierarchy mechanism）**：靠什么拉开主次？（字重 / 灰度 / 留白 / 单一强调色）。
3. **适用边界（Context boundary）**：适合什么密度和气质的产品？在什么场景下不能用？

### Step 4: 沙盒临摹与视觉找茬闭环 (Replication & Visual Critic Loop)
**临摹分级（2026-11-22 复盘定）**：日常临摹＝单对象级，按下述闭环执行；**深临摹**＝整页/整站级，每周至多 1 次——从本周已学对象中选最有价值的一个，周五复盘时定题、周六那轮以深临摹占用当日 1 个名额执行（其余 2 个名额照常）。深临摹产出全页/全站复刻件＋逐条差距清单（复刻不了的逐条写原因，不许拿替代品冒充），差距清单并入该对象完成报告。依据：获奖站整站复刻实证——状态联动、跨页一致性、媒体结构只有整站临摹才学得到，但成本约一下午，故限每周 1 次。
严禁只看不练。Agent 必须在本地沙盒完成“脱敏默写 → 视觉比对 → 像素纠偏”闭环：
1. **纯净重构**：基于提取的 Token 与解剖卡，用干净的语义化代码独立重写该组件，彻底剥离原网站的业务文案与冗余 DOM。
2. **并排视觉审查**：渲染本地组件并截图，与原网站组件截图并排提交给 Critic（视觉审查）视角，重点排查 4 项常见失真：
   - 边框颜色/透明度是否偏重，显得廉价？
   - 内边距（Padding）是否偏窄，导致呼吸感不足？
   - 字体字重或字距是否偏粗/偏挤？
   - 阴影或高光是否用力过猛？
3. **迭代修正**：根据挑刺意见修改代码并重新渲染，最多迭代 **3 轮**，直到视觉气质与克制程度高度逼近原版。
**分层验收（2026-11-23 kk 拍板 1A）**：临摹验收拆两层——**结构层**（tokens、布局、间距、状态与交互行为）是入库门槛，3 轮内逼近原版才算通过；**资产层**（照片纹理、专有字体字形、手绘/抠图形象的还原度）不阻断入库，差距逐条写进完成报告当「已知限制」。评审分工同步收紧：Critic 只判观感与结构（气质、层级、克制程度），不许拿估算数值挑刺；数值对错以 getComputedStyle 实测为准，评审估算与实测冲突时以实测裁决，并在纠偏记录里注明。

### Step 5: 结构化沉淀 (Pattern Commit)
只有通过 Step 4 结构层验证的对象（资产层差距按分层验收记录、不阻断），才允许写入本地模式库，沉淀形式只有一种：完成报告（`patterns/<pattern_id>.md`，按 `patterns/REPORT-TEMPLATE.md` 模板填写：基础档案／审美解剖／Tokens 与差值表／纠偏记录／视觉禁忌／纯净代码）。（2026-11-21 kk 定：直接用完成报告，YAML 不用了。）未通过验证的草稿直接丢弃、不入模式库、不出报告，但须在当日日志与汇报短消息中记一句**失败卡点**（具体卡在哪个样式或交互维度），避免丢失能力短板信号，不许静默丢弃。
