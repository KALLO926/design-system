# 设计体系总纲 · 实战工作流与自学习（整合版）

版本：2026-11-21 v2.2（基于 v2.1 修订运行节奏：每日自学习由 1 个对象增至 3 个，2026-11-22 kk 拍板）
定位：本文件为整个设计体系的唯一总纲，完整覆盖**「做设计（实战工作流）」**与**「养审美（自学习体系）」**两大引擎。判断正本为设计契约（`design-contract.md`），本文件与契约冲突时以契约为准。

## 一、体系总览与顶层纪律

两大引擎通过**共享中枢（设计契约 ＋ 模式库 ＋ 教训/反例库）**咬合运转：
- **自学习体系（输入端）**：每日按五步法逆向解剖真实优秀网站，沉淀已验证模式供实战调用。
- **实战工作流（输出端）**：按分级流程调用资产并完成交付，将 kk 的判定与项目教训回流至契约与反例库，每周五检查模式消费闭环并反哺学习权重。

### 顶层总纪律
1. **判断只有一个正本**：设计契约（`design-contract.md`）。kk 当场指令优先于一切成文规矩，冲突按晋升规则修订契约。
2. **判分的人不能是考试的人**：制作方自评分不作数，视觉验收靠无上下文盲审，**kk 的眼睛是最终否决**。
3. **没验证不许说完成**：交付前真打开、真运行、留证据；自学习未通过沙盒视觉验证，不算学会、不沉淀。

## 二、实战工作流（做设计）

### 流程总览与任务分级

接任务 → ①开工（读契约＋开工声明＋盘资产） → ②方向（三方向稿/kk 指认）
→ ③调研与资产（量测＋素材备齐） → ④制作（契约纪律＋资产调用＋前段技能）
→ ⑤审查（后段审查技能） → ⑥验收门（减法审查→机器门→盲审→状态抽查）
→ ⑦交付（双通道＋汇报） → ⑧回流（kk 判定入契约/反例，教训入教训录）

| 级别 | 适用范围 | 必须走的步骤 | 可跳过 |
|---|---|---|---|
| **L0 小修/微调** | 改文案、调间距、修局部 Bug、微调已有组件 | 读契约 → 修改 → 减法自查＋机器门 → 交付 | 方向稿、全量调研、视觉盲审 |
| **L1 常规设计** | 单页、核心功能模块、组件重构、已有品牌延展 | 完整流程（若 kk 已给明确风格锚，可免方向稿） | — |
| **L2 重度/全新** | 全新品牌、大型官网、从零建视觉体系 | 完整流程（强制三方向稿＋全量资产盘点＋四道验收门） | — |

### ① 开工
1. **先读契约**：开工前先读 `design-contract.md` 对齐判断基准；同时扫教训录与反例库的相关条目。
2. **先找技能**：先搜已有技能库，没有再找外部热门技能，评估（契合度、热度与维护、成本、与当家技能是否重复）过关才用。
3. **规格化理解**：拆解到可执行规格（目标一句话、冲突优先级、硬约束、规格与数字、元素级清单、验证方式）。能补齐的自己补齐，只问会改变结果的缺口；大任务或有歧义时先回规格化复述等 kk 点头。
4. **开工声明（3 行写死，L1+ 必做）**：视觉锚点、核心焦点（第一眼唯一落点是谁）、方向来源。写不出唯一焦点不许开工。
5. **先盘资产再做版式**：赢家赢在不可复制的资产（包装、人物、吉祥物、自有字体、真实摄影体系），版式只是入场券。开工前确认素材等级（实拍级/图库级/需生成），按等级定验收标准。

### ② 方向
- **联想探索（方向生成法，定方向前先行）**：从品牌名称、符号、产品能力、用户场景、文化背景提取核心线索，沿自然、艺术、科学、技术、情感多层联想；把有潜力的概念转译为构图、材质、字体、色彩、空间、动效或交互行为。优先与产品有关、表达鲜明、实现合理的；不强制隐喻、不堆叠所有创意、不直接复制参考作品；方向确认后停止无目的发散。**三方向稿的母题从这里长出来**（原文存档 `design-research-library/associative-exploration-2026-11-21.md`）。
- **默认先定方向**：「网格＋无衬线」不再是兜底，瑞士风不再是默认。L1+ 默认先出 **3 个实质分化方向稿**（首屏＋一个核心章节探路版）供 kk 指认或拼接；分化须在骨架/字体/排版/色彩/质感中至少三项不同，只换配色不算新方向。
- **例外**：kk 给了明确风格锚（点名风格、参考图指认）视为方向锁定，可免方向稿；kk 明说「别发散」或 L0 小修免方向稿。
- **对齐方式**：决定类对不齐用 `grill-me` 逐轮盘问（每题附推荐答案）；视觉类靠摆图指认，不靠文字描述。kk 只点风格形容词不算锁定方向。
- **形状在此定死**：几何语言（直角成系/圆润成系/不规则）属于品牌资产，在方向阶段定死，不许用 CSS 默认值凑合。
- 机器门与评审只跑选中方向，不给落选方向耗成本。

### ③ 调研与资产
- **看本体不看转述**：拆参考必须打开官网本体，逐张验图、核对对象身份；结论标注哪些没验到。
- **量测制**：必记数——主色色值与面积占比、标题/正文字号与层级比、图片尺寸与首屏占比、元素密度、关键圆角/间距。只有感觉词的调研不算完成；制作时逐项对照，交付前给差异清单。量测是为了看懂数值背后的道理再重新推导，不许原样搬版式与数值。
- **素材优先级**：实拍 ＞ 授权图库（Openverse/Wikimedia 的 CC 图/录像＋页脚署名）＞ AI 生成 ＞ 代码绘图（最后手段）。禁止无授权外链与盗图。
- **没有实物先造资产**：虚构或无实物品牌，开工前先用 AI 生成一套包装/产品资产当主角，不许跳过生成直接代码绘图。
- **常备资产调用**（查用路由以 `DESIGN-ASSETS.md` 为准）：已验证模式库 `patterns/`（做同类对象先查）、做法卡 `component-recipes`（78 种机制封顶，配套 `recipe-demos`）、Open Design 存档（借格式与量测参考，不作默认皮肤）、终末地等风格包（kk 点名才启用）、LIM 研究档案。

### ④ 制作（契约核心纪律摘要，全文以契约为准）
- **三词**：克制（敢不放，无关的再好看也不上）、编排（先定视线顺序与疏密节奏再摆放）、重心与让步（每屏只有一个视觉重心，其余变小、变淡、退后）。
- **硬禁区（命中即不交付）**：PPT 式设计（横条带堆叠、居中大标题＋卡片阵列、区块同构互不衔接）；大色块铺底分段（分段靠留白＋发丝线，颜色只长在小物件上；窄口例外：全页仅一处整幅深色带作节奏转折、目的明确时放行，见契约）；纸面/档案/复古纸质风；直角默认；首屏多层拦截（公告条＋弹窗＋Cookie＋聊天按钮同抢首屏）；网红模板三件套（蓝紫渐变＋弥散光晕＋大圆角阴影卡片阵列，非品牌点名不许成套）与纯装饰填充（悬浮图标、徽章堆砌、占位插画）。
- **空间与留白**：留白＝真空白（连底色都不涂）；空白要成片（段间 200–400px 量级），节奏靠密空交替；每屏只留一个主角，先删一半再往回加；间距按 4/8 步进、不写魔法数字，区块间留白 ＞ 区块内间距 2 倍。
- **形状**：照片只有三种待遇——整幅出血、大圆角、抠图无框，禁止矩形贴纸；全站圆角由一个变量管（token 化）。
- **颜色**：底色默认纯白或品牌定版底，全页一底到底；中性色占比 ≥85%，强调色只许 1 个、只长在核心 CTA 与关键状态。
- **排版与容器**：字体家族 ≤2；正文左对齐（极短标题除外）；层级靠字重、字号比、灰度拉开，不靠彩色文字；能用排版分组的不上容器，卡片嵌套 ≤2 层。
- **状态与焦点**：选中/按下态对比 ≥3:1（整块填充/完整描边/字重变化）；禁用态全站统一（默认整体 50% 不透明度）；键盘焦点必有独立焦点环（`:focus-visible`）；错误态只用唯一警示色、只长在边框与文字上；正文对比 ≥4.5:1。
- **图片纪律**：同一产品多配色拿母版图改色，不许分别生成；AI 生成整套图时把主体识别特征写进每张提示词、逐张验图；AI 生成人物忌过幼与塑料感。
- **字体本地自带（含单文件降级）**：工程项目一律使用本地字体文件，零外部字体请求；交付**单文件 `.html` 附件**时，英文字体可子集化（Subset）后 Base64 内联，中文字体或大体积字体允许降级为**系统无衬线字体栈（System Font Stack）**，严禁为内联整包中文字体导致文件体积失控。
- **Web 代码**：写或改前端代码先查 Modern Web Guidance 对应指南再动手；框架项目拼组件可用 UI SDK（行为库）与既有组件资产，但不进单文件主流水线。

### ⑤ 六技能流水线（贯穿制作与审查，全局唯一默认工作流）
顺序固定，职责不重叠：
- **前段（②方向 / ④制作 阶段触发）**：
  1. `frontend-design`：定审美方向（骨架、气质、母题）。
  2. `design-taste-frontend (taste-skill)`：页面级反 slop 检查与结构约束。
  3. `ui-ux-pro-max`：查配色/字体/UX 规则——只查不定向，无配色决定权，与方向组冲突直接否决。
- **后段（⑤审查 阶段触发）**：
  4. `better-*`（`better-interface` 编排，含 ui/typography/colors/layout/accessibility/writing）：最终界面审查。
  5. `web-design-guidelines`：可访问性与工程细节审查（规则原文用本地副本）。
  6. `impeccable`：机械检测器收尾。
- **仲裁序位**：`impeccable` 机械事实（P0 一票阻断）＞ `web-design-guidelines` 工程与无障碍底线（P1 必改或留痕豁免）＞ `better-*` 审美建议（标 CANDIDATE，只采纳高价值项，不无限返工）。
- **分支（不进主流水线）**：动效判断走 Emil 技能组＋GSAP 实现；Unslop 与 cook 仅在 kk 点名时调用；视频类按对象分工（宣传片 `video-shotcraft`、功能演示 `onetake`、抽象概念 `local-anatomy`、真实机器 `teardown`）。

### ⑥ 验收门（四道，L1+ 全过才交付）
1. **减法审查（制作方自查，先于盲审）**：删装饰、扩留白（密度窒息加 20–30%）、压噪音（次要信息降对比/字号）、查红线（对契约硬禁区与反例库）。四项过完才送盲审。
2. **机器门**：后段审查＋`impeccable` 检测零 P0（仅算合规门，不算视觉验收）。
3. **视觉盲审（含熔断机制）**：另开无上下文子 agent，只看成品截图（桌面＋手机、默认状态；动效看真实录屏），不给源码与过程，按设计/可用性/创意/内容四项打分并逐条给位置＋改法；对照反例库核查。设计分 ＜7 或 P0 级观感问题（主体缺席、母题误读、留白失控、多图主体不一致、压图文字不可读）不许交付，先返工再复审。
   - **熔断规则**：盲审返工最多 **2–3 轮**。若达上限仍未过线，立即停止空转，将「当前最优版＋盲审未过原因＋具体卡点」呈报 kk 拍板。
4. **状态抽查（制作方实测）**：hover/focus/selected/disabled 四态实测，键盘 Tab 走焦点路径，真实浏览器量对比度，结果写入交付报告。

### ⑦ 交付
- **双通道**：单文件 `.html` 附件 ＋ App 内 Space 版各一份（安卓端用 Space 版看）。
- **防旧版**：改版一律换新文件名（带 `_v2/_v3` 或日期后缀），禁止同名覆盖；网页 artifact 改版明说版本号并提醒从完成卡重开。
- **附件规范**：英文文件名；图片一次一张；大文件（约 12MB+）改走下载链接。
- **动效交付**：预览必须嵌真实录制的循环短片（截图＋推拉＋叠化＝幻灯片，不算视频）。
- **交付汇报（人话版）**：先人话摘要（首句讲可感知变化与原因），后技术细节；附测试证据（跑了什么、结果如何、kk 如何自验；未验写明原因）；需拍板项列带推荐倾向的编号选项。

### ⑧ 回流
- **kk 的判定**（点赞/否决/纠正/明令）→ 当轮直入契约对应节，否决同时入反例库（契约＋反例库即 Veto Log，不另建日志）。
- **项目教训** → 每个项目结束往 `design-lessons.md` 记 ≤2 条。
- **自学结论** → 先记教训录，同类第二次互证或经项目验证才晋升契约；与契约冲突标「待裁决」等 kk 拍板。

## 三、自学习体系（养审美）

### 核心框架与三条原则
- **三层架构**：判断层（`design-contract.md`）＋ 方法层（`ui-pattern-learner/SKILL.md`）＋ 范围层（L1–L4 维度与六类素材）。
- **三条原则**：学底层秩序与工程工艺（不学视觉表皮）；学关系不背数值；未通过沙盒视觉验证不算学会、不沉淀。

### 唯一自学习方法：五步法
学习对象涵盖组件、区块、页面模式、排版系统、交互/状态系统。
- **Step 1 计算样式采样**：无头浏览器打开目标页面定位对象，调用 `getComputedStyle()` 提取真实渲染值（排版比例、低透明度边框、相邻层级背景明度差、阴影、padding/gap/border-radius，并验同心圆角法则）。严禁将原始 HTML/CSS 源码塞进知识库。
  - *登录墙降级规则*：遇登录墙优先切至公开 Demo / Sandbox / Storybook；无公开态则跳过换素材池下一个对象，严禁空转。强登录高价值产品留待 kk 提供已登录态或截图再拆。
- **Step 2 状态差值采集**：实际触发 hover、focus-visible、active、disabled 及明暗切换，记录变化前后差值与动效参数（`transition-property`、`duration`、`cubic-bezier` 原值）；带边缘态（空状态、加载/骨架、报错、文本溢出）一并采样。
- **Step 3 双模态解剖**：截图与采样数据对照，必答三问——克制点（刻意去掉了什么）、层级手段（靠什么拉开主次）、适用边界（适合/禁用场景）。品牌语境与立场只记录观察、不下结论。
- **Step 4 沙盒临摹闭环**：用干净语义代码独立重写（剥离原文案与业务 DOM），渲染截图与原对象并排交无上下文评审挑刺（边框是否偏重、padding 是否偏窄、字重字距是否偏粗偏挤、阴影高光是否过猛），按意见改，最多 **3 轮**，逐轮留纠偏记录。
- **Step 5 沉淀与失败归档**：通过验证按模板写《UI 模式学习完成报告》入库；未通过的草稿直接丢弃不入模式库，但须在当日日志与短消息记一句**失败卡点**。

### 范围、人机分工与素材池
- **学习维度与分工**：
  - **L1 秩序感与微弱层级**（排版比例、4/8 步进、同心圆角、低透明边框与明度差）：Agent 主学，kk 定底线。
  - **L2 边缘状态与微交互**（空/加载/报错/溢出态、状态差值与缓动）：Agent 主学，kk 定底线。
  - **L3 信息密度与「藏」的艺术**（渐进式披露、高密度灰度降噪）：Agent 学＋减法循环纠偏，核心架构与取舍归 kk。
  - **L4 语境、立场与设计决策**（品牌性格、打破规矩、跨学科隐喻）：归 kk；Agent 只记观察，跨媒介素材由 kk 点名才执行。
- **素材六类（轮换，非封闭清单）**：①品牌官网与落地页；②高密度生产力工具；③金融与数据面板；④无头与原子组件库（Agent 必学）；⑤编辑部与内容网站；⑥真实上线的优秀网站（品类不限）。
  - 素材池维护在 `learning-sources.md`：核实为真实上线、质量过硬且**可无登录墙访问（或带公开 Demo / Storybook）**才入池；索引站/图库站只作发现渠道。
- **避坑三条**：不学概念飞机稿（Dribbble/Behance 炫技图）；不学「静态成功态」（功能型产品优先学内部界面与边缘态）；不背固定色板与样式。

### 唯一沉淀格式：《UI 模式学习完成报告》
存 `patterns/<pattern_id>.md`（模板正本 `patterns/REPORT-TEMPLATE.md`），含六节：①基础档案；②审美解剖与克制逻辑；③核心 Tokens 与交互差值（表格）；④沙盒临摹与视觉纠偏记录；⑤提取的视觉禁忌；⑥已验证的纯净代码。
- 报告外分流：通用结论进教训录（每轮 ≤2 条）；视觉禁忌与 kk 否决进反例库。

### 运行节奏
- **每日约 10:50（`daily-design-learning`）**：先读契约 → 按五步法学**三个对象**（2026-11-22 kk 拍板由 1 个增至 3 个；分属不同素材类别，非组件类至少 2 个、组件类最多 1 个，质量闸不降）→ 回扫过去 24h kk 判定维护契约 → 发一条短消息，逐个报学了什么、关键数据、是否通过（**通过附沉淀路径，未通过附一句失败卡点**）。
- **仅周一加做**：调研库三轨搜集（完整工作流复盘／有仓库或演示可拆的项目／论文与设计技能），新增 6–10 条，逐条打开本体核实。
- **每周五晚（`weekly-design-review`）**：①复盘本周通过率与高频**失败卡点**；②**消费闭环检查**（统计本周实战项目调用了哪些 Pattern，识别“只存不用”盲区，动态调整下周六类素材轮换权重）；③整理资产（去重、对账、守上限）与架构优化（大改只提案等 kk 拍板），发周报简报。
- *已停用旧办法（2026-11-21 起）*：品牌站印象式深拆、单独外出搜集外部反例、YAML 模式文件。
